## Same-PR correction ruling

QA-GOV-010 does not require an organically arising software defect. An honest
pending-to-observed evidence correction can exercise its same-PR requirement.
The initial report must accurately identify unavailable facts as pending and
must never claim complete release acceptance. Once real host facts exist, an
independent reviewer must identify the concrete required completion/correction
before merge. The developer records those observations on that same open PR,
with changed-head invalidation and renewed required reviews.

This is meaningful completion of owed release documentation, not a manufactured
bug, deliberately inaccurate report, sacrificial PR or waived review. The live
transcript must call it an evidence correction; it cannot claim to have observed
or fixed a code defect. QA must assess the actual correction and its receipts
before accepting the live trace.

## No self-referential review loop

The committed report may record observations and review IDs for earlier PR2
heads, accurately bound to those heads. It must not present them as approval of
the final head. Current final-head review/check evidence stays in authenticated
host observations and the locked runtime record; updating the report to name its
own future approval or merge is not required. J-bound activation, cleanup and
admission also remain runtime observations, as the addendum specifies.

This reads the addendum's separate evidence boundaries and I-stage report scope
together; no design-text change is required for this interpretation. Tests must
cover stale-head rejection, both readiness boundaries, duplicate delivery,
restricted diffs, and completion/admission through J. Final independent Staff
and AppSec implementation reviews remain mandatory on the corrected revision.
